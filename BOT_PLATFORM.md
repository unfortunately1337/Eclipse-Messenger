# Платформа ботов Eclipse

Ботов создают в системном чате Eclipse: меню → Боты → Создать бота. Имя, уникальное имя, необязательный аватар. Новые юзернеймы должны оканчиваться на bot без учёта регистра; 4–32 символа вместе с окончанием. Уже созданные боты сохраняют свои адреса. После регистрации — подтверждение, токен и inline-кнопка копирования. Создание не обращается к внешней программе и не проверяет работоспособность API.

В «Мои боты» доступны токен, отзыв токена и удаление с подтверждением. В настройках можно изменить имя, уникальное имя и аватар. При смене уникального имени проверяются занятость и окончание bot; токен сохраняется. Отзыв меняет ключ и отключает webhook, сохраняя очередь для новой программы. Удаление уничтожает профиль, переписки, события и ключи бота.

## API v1

Адрес: https://ВАШ_СЕРВЕР/api/bot/v1/МЕТОД. POST JSON с Authorization: Bearer ТОКЕН; ответ {ok:true,data:...}. Внешней программе не нужны пользовательские cookie или CSRF. Токен передаётся только заголовком.

Документация: /bot-api. OpenAPI 3.1: /api/bot/v1/openapi.json. SDK и рабочий пример: [sdk/eclipse-bot/README.md](sdk/eclipse-bot/README.md).

Методы: getMe, getUpdates, sendMessage, editMessageText, deleteMessage, getChat, uploadFile, getFile, sendPhoto, sendVideo, sendVoice, sendAudio, sendDocument, sendVideoNote, sendSticker, sendMediaGroup, setMyCommands, getMyCommands, setMyChatSettings, getMyChatSettings, setChatSettings, getChatSettings, setWebhook, deleteWebhook, getWebhookInfo, answerCallbackQuery, sendChatAction. Старый адрес /api/bot/v1/me сохранён.

setMyChatSettings задаёт оформление всех чатов бота: empty_text — текст пустого чата (до 2048 символов), input_placeholder — подсказка поля ввода (до 128), menu — меню команд, произвольная клавиатура или отсутствие меню. setChatSettings задаёт отдельные параметры начатой переписки; settings:null возвращает наследование общих настроек. Обновления частичные, сохраняются в БД и появляются в открытом чате. Клавиатура поддерживает до 8 строк по 4 кнопки: отправка текста/команды, callback_data (до 64 байт) или HTTPS-ссылка. Callback нижнего меню не создаёт сообщение: программа получает callback_query.source:"menu" и callback_query.chat.id. Команды и ответы определяет программа разработчика.

События: message, edited_message, callback_query. /start — обычное сообщение, его поведение определяет программа. setMyCommands регистрирует команды меню в поле ввода. Inline-кнопки передаются в reply_markup; callbacks доступны только пользователю соответствующего чата и действующей кнопке сообщения.

Бот отвечает после первого сообщения пользователя. Файлы связаны с чатом: uploadFile(chat_id) → file_id → метод отправки. getFile принимает file_id или media.src входящего события. download_path скачивается с Bearer токеном. Альбом — одно нативное сообщение с 2–6 элементами. Текст без HTML/Markdown-парсинга. editMessageText заменяет текст и клавиатуру; отсутствие reply_markup убирает кнопки.

## Доставка

События и содержимое сообщений зашифрованы в PostgreSQL. update_id монотонен внутри бота. События хранятся 7 дней. getUpdates: offset, limit 1–100, timeout 0–25 секунд. offset = последний успешно обработанный ID + 1 подтверждает предыдущие события. Один polling-процесс на бота; несколько обработчиков подключайте через свою очередь.

Webhooks доставляет встроенный Node worker при запущенном сервере Next. Публичный HTTPS, порт 443, без редиректов. Получатель проверяет X-Eclipse-Bot-Secret-Token. Один запрос на бота одновременно, порядок update_id, повторы с задержкой до часа. Очередь переживает перезапуск сервера. Несколько серверных процессов используют SQL-блокировки и lease. getUpdates при активном webhook возвращает 409.

Доставка как минимум один раз: разработчик обязан учитывать повторы. request_id — UUID для sendMessage и методов отправки медиа. Повтор с прежним содержимым возвращает прежнее сообщение, с другим — 409. В SDK requestId(action) создаёт стабильный UUID ответа на событие. Ошибки webhook не содержат URL, секрет или тело события.

## Границы и развёртывание

Версия v1 обслуживает личные чаты с ботами. Группы/каналы пока не подключены к событиям ботов и правам администрирования. Секретные чаты с ботом запрещены. API не даёт доступ к обычным чатам, контактам или E2EE-ключам. Переписка с ботом доступна его программе и серверу Eclipse: TLS при передаче и шифрование при хранении, без пользовательского E2EE. Человеческие и секретные переписки сохраняют свой транспорт.

Лимиты: 120 запросов в минуту на бота, 16 384 символа текста, 4096 подписи, 20 МиБ файла; 8 строк inline-кнопок по 4 кнопки. При 429 соблюдайте Retry-After. Токен проверяется по хешу; копия владельца, webhook URL и secret зашифрованы. Внутренние/зарезервированные адреса webhook отклоняются, соединение закреплено за проверенным DNS-адресом.

Локально: http://localhost:3000. Для внешних разработчиков разверните Eclipse на публичном HTTPS-домене. Нужны PostgreSQL, Redis, долговременные ключи шифрования и хранилище медиа. Примените миграции Prisma, сгенерируйте клиент, перезапустите сервер. Для webhook нужен постоянно работающий Node-процесс: serverless не гарантирует жизнь встроенного worker. Polling не требует фонового worker.

## Проверка реализации

Миграция 20261003120000_bot_api применена; 46 миграций, схема актуальна. Проверены TypeScript, ESLint новых файлов, 41 Vitest-тест и 4 SDK-теста. Через настоящий HTTP API проверены независимые боты, изоляция чатов/файлов, параллельный повтор /start, идемпотентность ответов, callbacks, редактирование/удаление, документы с именем файла, фото/стикер/альбом, offset, long polling и отзыв токена во время ожидания. Также проверены окончание bot, принятие смешанного регистра, сохранение черновика после ошибки, повторная проверка старого черновика на шаге аватара, короткие сообщения и предупреждение о токене. Старые боты без окончания bot продолжают работать. В Chrome проверены ПК и мобильная версия, сохранение черновика при ответе, команды и callbacks; отдельно — отправка фото, запись голоса/кружка, получение вложений программой и ответы через API. Обычные E2EE-переписки прошли регрессионную проверку текста, фото, файла, голоса и кружка. Доставка webhook, lease, порядок и повторы проверены с подменённым HTTPS-транспортом; внешний публичный webhook в этих проверках не использовался.

Диагностические сценарии, логи и снимки находятся в игнорируемой папке scratch и не предназначены для коммита. Публикация сервера в интернет не выполнялась.

Дополнение: миграция 20261003230000_bot_chat_customization применена, теперь 47 миграций. Для оформления чата и переименования проверены 14 Vitest-тестов, 5 SDK-тестов, TypeScript и ESLint. Через настоящий API и Chrome на ПК и мобильном проверены смена имени/юзернейма, коллизии и сохранение токена, собственная плашка/подсказка/клавиатура, callbacks без сообщения, ответы программы, идемпотентность, изоляция пользователей/ботов, живые обновления, скрытое меню, команды, отдельные настройки переписки и сброс наследования.
